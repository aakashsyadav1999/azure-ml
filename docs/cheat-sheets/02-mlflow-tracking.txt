MLflow Tracking and Model Comparison Guide
==========================================

This guide covers how to use MLflow for experiment tracking, model comparison, and performance monitoring in Azure ML.

1. MLFLOW BASICS
---------------
a. What MLflow Provides:
   - Experiment tracking (runs, parameters, metrics)
   - Model registry and versioning
   - Model comparison and visualization
   - Artifact storage (models, plots, data)

b. Azure ML Integration:
   - Automatic MLflow backend setup
   - Built-in experiment UI
   - Model registry integration
   - Artifact storage in Azure

2. TRACKING EXPERIMENTS
----------------------
a. Start Tracking Run:
   ```python
   import mlflow
   
   with mlflow.start_run(run_name="iris_training_run"):
       # Your training code here
       pass
   ```

b. Log Parameters:
   ```python
   # Log hyperparameters
   mlflow.log_param("model_type", "RandomForest")
   mlflow.log_param("n_estimators", 100)
   mlflow.log_param("max_depth", 10)
   ```

c. Log Metrics:
   ```python
   # Log performance metrics
   mlflow.log_metric("accuracy", 0.95)
   mlflow.log_metric("f1_score", 0.94)
   mlflow.log_metric("precision", 0.96)
   ```

d. Log Artifacts:
   ```python
   # Log model
   mlflow.sklearn.log_model(model, "trained_model")
   
   # Log files
   mlflow.log_artifact("confusion_matrix.png")
   mlflow.log_artifact("feature_importance.csv")
   ```

3. MODEL COMPARISON IN AZURE ML
-------------------------------
a. Access Experiments:
   - Azure ML Studio → Jobs → Experiments
   - Select experiment (e.g., "iris-classification")
   - View all runs and their metrics

b. Compare Runs:
   - Select multiple runs (checkbox)
   - Click "Compare" button
   - View side-by-side metrics
   - Analyze parameter impact

c. Visualizations:
   - Metric plots over time
   - Parameter vs metric scatter plots
   - Run comparison tables
   - Artifact downloads

4. MODEL REGISTRY
----------------
a. Register Models:
   ```python
   # Register model to Azure ML
   model_uri = f"runs:/{run_id}/trained_model"
   mlflow.register_model(model_uri, "iris-classifier")
   ```

b. Model Versions:
   - Each registration creates new version
   - Version numbers auto-increment
   - Can promote versions (Staging → Production)

c. Model Metadata:
   - Description and tags
   - Performance metrics
   - Training run lineage
   - Approval status

5. ADVANCED TRACKING PATTERNS
-----------------------------
a. Nested Runs:
   ```python
   with mlflow.start_run(run_name="model_comparison"):
       for model_name, model in models.items():
           with mlflow.start_run(nested=True, run_name=model_name):
               # Train and log individual model
               pass
   ```

b. Custom Metrics:
   ```python
   # Log multiple metrics at once
   metrics = {
       "train_accuracy": train_acc,
       "test_accuracy": test_acc,
       "train_loss": train_loss,
       "test_loss": test_loss
   }
   mlflow.log_metrics(metrics)
   ```

c. Model Signatures:
   ```python
   from mlflow.models.signature import infer_signature
   
   signature = infer_signature(X_train, model.predict(X_train))
   mlflow.sklearn.log_model(model, "model", signature=signature)
   ```

9. TROUBLESHOOTING MLFLOW
------------------------
a. Missing Metrics:
   - Check MLflow imports in scripts
   - Verify mlflow.start_run() usage
   - Ensure metrics are logged before run ends

b. Authentication Issues:
   - MLflow uses Azure ML workspace auth
   - Ensure proper Azure credentials
   - Check workspace permissions

c. Artifact Storage:
   - Artifacts stored in Azure ML workspace
   - Check storage account permissions
   - Verify file paths and sizes

10. BEST PRACTICES
-----------------
a. Naming Conventions:
   - Use descriptive run names
   - Include timestamps for uniqueness
   - Tag runs with environment/purpose

b. Metric Organization:
   - Log both training and validation metrics
   - Use consistent metric names
   - Include data quality metrics

c. Artifact Management:
   - Log models with clear names
   - Include plots and reports
   - Document artifact contents

d. Model Lifecycle:
   - Register only production-ready models
   - Use staging for testing
   - Archive old model versions

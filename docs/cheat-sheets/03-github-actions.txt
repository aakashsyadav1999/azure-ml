GitHub Actions MLOps Workflow Guide
===================================

This guide explains the GitHub Actions workflows for automated MLOps with Azure ML.

1. WORKFLOW STRUCTURE
--------------------
a. Development Workflow (train_model_dev.yml):
   - Triggers: Push to dev branch, manual dispatch
   - Environment: Development
   - Purpose: Fast feedback for experimentation

b. Production Workflow (train_model_prod.yml):
   - Triggers: Push to main/master branch
   - Environment: Production  
   - Purpose: Stable production deployments

2. WORKFLOW COMPONENTS
---------------------
a. Trigger Configuration:
   ```yaml
   on:
     push:
       branches: [dev]
       paths: ['Pipeline/**', 'environments/**']
     workflow_dispatch:
   ```

b. Permissions:
   ```yaml
   permissions:
     id-token: write  # Required for Azure login
     contents: read
   ```

c. Environment Variables:
   ```yaml
   env:
     PYTHON_VERSION: '3.9'
   ```

3. JOB STEPS BREAKDOWN
---------------------
a. Checkout Code:
   ```yaml
   - uses: actions/checkout@v4
   ```

b. Setup Python:
   ```yaml
   - uses: actions/setup-python@v5
     with:
       python-version: ${{ env.PYTHON_VERSION }}
   ```

c. Install Dependencies:
   ```yaml
   - name: Install dependencies
     run: pip install azure-ai-ml azure-identity azure-cli
   ```

d. Azure Authentication:
   ```yaml
   - uses: azure/login@v1
     with:
       client-id: ${{ secrets.AZURE_CLIENT_ID }}
       tenant-id: ${{ secrets.AZURE_TENANT_ID }}
       subscription-id: ${{ secrets.AZURE_SUBSCRIPTION_ID }}
   ```

e. Configure Azure ML:
   ```yaml
   - name: Create Azure ML config
     run: |
       mkdir -p .azureml
       cat > .azureml/config.json << EOF
       {
         "subscription_id": "${{ secrets.AZURE_SUBSCRIPTION_ID }}",
         "resource_group": "${{ secrets.AZURE_RESOURCE_GROUP }}",
         "workspace_name": "${{ secrets.AZURE_WORKSPACE_NAME }}"
       }
       EOF
   ```

f. Run Pipeline:
   ```yaml
   - name: Submit training pipeline
     run: |
       python Pipeline/deploy-train.py \
         --model-name "iris-classifier" \
         --experiment-name "iris-classification-dev"
   ```

4. ENVIRONMENT SETUP
-------------------
a. Create Environments:
   - GitHub repo → Settings → Environments
   - Create "Development" and "Production"
   - Configure protection rules if needed

b. Environment Secrets:
   - Each environment has its own secrets
   - Allows different Azure subscriptions/workspaces
   - Enables proper dev/prod separation

c. Environment Variables:
   - Configure environment-specific settings
   - Override default values per environment
   - Support feature flags and configurations

5. WORKFLOW TRIGGERS
-------------------
a. Push Triggers:
   ```yaml
   push:
     branches: [dev]
     paths:
       - 'Pipeline/**'
       - 'environments/**'
       - '.github/workflows/**'
   ```

b. Manual Triggers:
   ```yaml
   workflow_dispatch:
     inputs:
       model_name:
         description: 'Model name'
         required: false
         default: 'iris-classifier'
   ```

c. Scheduled Triggers (optional):
   ```yaml
   schedule:
     - cron: '0 2 * * 1'  # Weekly on Mondays at 2 AM
   ```

6. USING WORKFLOW INPUTS
-----------------------
a. Access Input Values:
   ```yaml
   - name: Use input value
     run: |
       echo "Model name: ${{ github.event.inputs.model_name }}"
       python Pipeline/deploy-train.py \
         --model-name "${{ github.event.inputs.model_name || 'default-model' }}"
   ```

b. Conditional Execution:
   ```yaml
   - name: Deploy to production
     if: github.ref == 'refs/heads/main'
     run: echo "Deploying to production"
   ```

7. MONITORING WORKFLOWS
----------------------
a. Workflow Status:
   - GitHub repo → Actions tab
   - View running/completed workflows
   - Check logs for each step

b. Notifications:
   ```yaml
   - name: Success notification
     if: success()
     run: echo "✅ Pipeline completed successfully!"
   
   - name: Failure notification
     if: failure()
     run: echo "❌ Pipeline failed!"
   ```

c. Slack/Teams Integration:
   ```yaml
   - name: Notify Slack
     if: always()
     uses: 8398a7/action-slack@v3
     with:
       status: ${{ job.status }}
       webhook_url: ${{ secrets.SLACK_WEBHOOK }}
   ```

8. WORKFLOW BEST PRACTICES
--------------------------
a. Job Organization:
   - Keep jobs focused and atomic
   - Use job dependencies (needs:)
   - Parallel execution where possible

b. Secret Management:
   - Use environment-specific secrets
   - Rotate secrets regularly
   - Limit secret scope

c. Error Handling:
   ```yaml
   - name: Handle errors
     if: failure()
     run: |
       echo "Pipeline failed at step: ${{ github.job }}"
       # Send alerts, cleanup resources, etc.
   ```

d. Caching:
   ```yaml
   - name: Cache pip dependencies
     uses: actions/cache@v3
     with:
       path: ~/.cache/pip
       key: ${{ runner.os }}-pip-${{ hashFiles('**/requirements.txt') }}
   ```

9. TROUBLESHOOTING WORKFLOWS
---------------------------
a. Authentication Issues:
   - Check GitHub secrets configuration
   - Verify Azure service principal permissions
   - Test Azure CLI login locally

b. Pipeline Failures:
   - Check Azure ML workspace status
   - Verify compute cluster availability
   - Review Azure ML job logs

c. Workflow Debugging:
   ```yaml
   - name: Debug workflow
     run: |
       echo "GitHub ref: ${{ github.ref }}"
       echo "Event name: ${{ github.event_name }}"
       echo "Actor: ${{ github.actor }}"
       az account show
   ```

10. ADVANCED PATTERNS
---------------------
a. Matrix Strategy:
   ```yaml
   strategy:
     matrix:
       model: [random-forest, logistic-regression, svm]
   steps:
     - name: Train model
       run: python train.py --model ${{ matrix.model }}
   ```

b. Workflow Dependencies:
   ```yaml
   jobs:
     train:
       runs-on: ubuntu-latest
       steps: [...]
     
     deploy:
       needs: train
       if: github.ref == 'refs/heads/main'
       steps: [...]
   ```

c. Reusable Workflows:
   ```yaml
   # .github/workflows/reusable-train.yml
   on:
     workflow_call:
       inputs:
         environment:
           required: true
           type: string
   ```

11. WORKFLOW LIFECYCLE
---------------------
a. Development Flow:
   1. Create feature branch
   2. Push to dev → triggers dev workflow
   3. Review results in Azure ML
   4. Create PR to main

b. Production Flow:
   1. Merge PR to main
   2. Auto-trigger production workflow
   3. Model deployed to production
   4. Monitor performance

c. Rollback Strategy:
   1. Revert commit on main
   2. Re-trigger production workflow
   3. Previous model version restored
